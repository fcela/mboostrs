# Agentic discovery benchmark v4 ("hostile workflows") — protocol

Run date: 2026-10-12. This battery tests whether autonomous analysis agents,
working through mboostrs (or a competitor toolkit), handle hostile data
conditions: missing values, target leakage, heteroscedasticity, confounding,
steep-but-smooth transitions, and real data scored on a sealed test set.

Per project convention all benchmarks are recorded in the docs; this file and
the [graded report](agentic_hostile_workflows_report.md) are the record of
this battery. Battery materials (CSVs, truth key, agent reports) live in
`docs/benchmarks/agentic_hostile_workflows/`.

## Cases

Six datasets, generated by `gen_v4.py` (shipped in the battery directory;
rerunnable). All synthetic predictors are U(0,1) unless noted.

| Case | Rows | Columns | Planted structure |
|---|---|---|---|
| missingness | 600 | x0..x5, y | x0 kink at 0.40 (flat below, +2.5/unit above); x2 sine (amp 1.5, peak 0.5); x3 linear (+1.0); x1,x4,x5 noise. MCAR NaN at 10% in x0 and x2. |
| leakage | 600 | x0..x3, post, y | x0 linear (+2.0); x1 sine (amp 1.5, peak 0.5); x2,x3 noise. `post = y + N(0,0.05²)`, cor(post,y)=0.9986 — a downstream proxy of the target, i.e. leakage, not a legitimate predictor. |
| heteroscedastic | 800 | x0..x4, y | Mean: 2.0·x0 + 1.5·sin(π·x1); x3,x4 noise. sd(y|x) = 0.25 + 1.5·x2 (~13× variance ratio between top and bottom x2 quartiles). |
| confounding | 600 | x0, g, x1, x2, y | Within-group: y = 1.5·x0 − 2.0·g + noise; x1,x2 noise. x0 correlates with the 0/1 group indicator g, so the marginal x0→y slope is −1.352 (Simpson reversal vs the within-group +1.5). |
| sharp_smooth | 800 | x0..x3, y | x0: 3.0·logistic(6·(x0−0.5)) — steep but continuous, NO jump; x1 linear (+1.5); x2,x3 noise. Steepness k=6 was chosen as the steepest setting the discontinuity screen types fully smooth (k=8/10/25 typed jumps). |
| real | 354 train | age,sex,bmi,bp,s1..s6, y | sklearn diabetes dataset (loaded offline), random 80/20 split, seed 406 → 354 train / 88 sealed test rows. No planted truth; graded by held-out RMSE. |

Build validation (all hold): missingness NaN rates 10.8%/10.3%; leakage
cor(post,y)=0.9986; heteroscedastic oracle mean coefs 2.008/1.557;
confounding within-group slope 1.630; sharp_smooth oracle coefs 2.984/1.433
with the discontinuity screen typing nothing as a jump; real train/test
disjoint. Full validation numbers are in `BUILD_NOTES.md` in the battery
directory. The sealed test rows are withheld from the repo to preserve
benchmark integrity (see the truth key).

## Arms (3 per case = 18 runs)

- **A — mboostrs + skills.** Model only with mboostrs; read the two shipped
  agent skill files first and follow them.
- **B — sklearn/XGBoost.** scikit-learn and xgboost only; no mboostrs.
- **C — mboostrs, no skills.** Model only with mboostrs; work from docstrings
  and `help()` only; do not read the skill files.

Python: the project's venv (mboostrs installed); pandas/numpy/polars allowed
for data handling. Frozen prompts were identical across arms except the
toolkit paragraph and the per-case trap section. Budget: ~40 minutes per run.
Agents were forbidden from reading the truth key, the package source, or any
data-generator code; every claim had to come from their own analysis.

Each case's prompt named its trap explicitly ("Some predictor columns contain
missing values"; "One of the columns may not be a legitimate predictor"; "Do
not assume the noise variance is constant"; "The marginal association ...
need not equal its association once other variables are accounted for";
"decide carefully whether it is a genuine discontinuity"). The benchmark
tests whether agents carry out the analysis needed to handle each condition
after it is identified.

Deliverable per run: a Markdown findings report (effects found with evidence,
what was ruled out, methods/seeds/fit counts, wall-clock time) plus a
case-specific section (missingness handling; leakage assessment; variance
analysis; association-vs-causation; jump-vs-steep-smooth; out-of-sample
honesty). The `real` case additionally required a pickled final model and a
one-line PREDICT spec, applied by the grader to the sealed test features.

## Grading

Grading rubric: scorecard dimensions D1, D2, D3, D5, D8, D10 (1–5 each;
D4/D6/D7/D9 n/a), plus per-run efficiency metrics (wall-clock, fit counts)
recorded but not scored, feeding the skills-value question (issue #492).

- D1 relationship discovery: per-case criteria (leak caught; reversal
  reported; variance attributed; steep-smooth not called a jump; real =
  held-out RMSE tertile rank + calibration honesty).
- D2 uncertainty honesty: soft numbers flagged as soft, no causal overreach,
  CV-vs-test gaps owned.
- D3 method fit, D5 reproducibility, D8 tool fluency (a broken PREDICT spec
  fails D8 outright), D10 communication.

Truth values and the full rubric are in the battery directory
(`TRUTH_KEY.json` with the sealed rows withheld, `RUBRIC.md` summarized here).
